# Requirements: FitAcademy

**Defined:** 2026-10-01
**Core Value:** A user can quickly log what they eat and how they train, and get back clear, explainable coaching that tells them what to change — instead of just raw numbers.

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Account & Auth

- [ ] **AUTH-01**: User can create an account with email and password
- [ ] **AUTH-02**: User can log in and stay logged in across app restarts (short-lived access token + rotating refresh token)
- [ ] **AUTH-03**: User can log out from the app
- [ ] **AUTH-04**: User can reset a forgotten password via an emailed link
- [ ] **AUTH-05**: User gives explicit health-data consent at signup and can withdraw it from settings
- [ ] **AUTH-06**: User can only ever read or change their own data; admin-only functions are restricted to the admin role

### Profile & Targets

- [ ] **PROF-01**: User can set timezone, language (EN/RO), units, sex, height, and date of birth
- [ ] **PROF-02**: User can choose a goal (fat loss, maintenance, muscle gain) and activity level
- [ ] **PROF-03**: User gets daily calorie and macro targets computed from their profile and goal
- [ ] **PROF-04**: Targets never go below a safe calorie floor or above a safe weekly rate of change; users under 18 or underweight cannot select a fat-loss goal
- [ ] **PROF-05**: User can see a "how we calculated this" breakdown of their targets
- [ ] **PROF-06**: User can manually override their calorie and macro targets
- [ ] **PROF-07**: User can log bodyweight and see a smoothed trend line over time
- [ ] **PROF-08**: Changing targets does not alter how past days are evaluated (targets kept as history)

### Nutrition

- [ ] **NUTR-01**: User can search foods by name in English or Romanian (with or without diacritics)
- [ ] **NUTR-02**: User can log a food to a meal (breakfast, lunch, dinner, snack) with a serving or gram amount
- [ ] **NUTR-03**: User can edit or delete a logged food entry
- [ ] **NUTR-04**: User can see a daily summary of calories and macros against their targets
- [ ] **NUTR-05**: User can browse past days' logs and summaries
- [ ] **NUTR-06**: User can create custom foods with their own macros
- [ ] **NUTR-07**: User can mark foods as favorites and pick from them quickly
- [ ] **NUTR-08**: User sees recent and frequent foods first when logging
- [ ] **NUTR-09**: User can quick-add calories/macros without choosing a food
- [ ] **NUTR-10**: User can copy a meal or an entire previous day into today
- [ ] **NUTR-11**: Past log entries keep their original nutrition values even if the food is later edited
- [ ] **NUTR-12**: Each log is assigned to the correct day in the user's own timezone

### Barcode

- [ ] **BARC-01**: User can scan a product barcode with the phone camera and log the matched food
- [ ] **BARC-02**: Common Romanian packaged products are found instantly (pre-imported from Open Food Facts)
- [ ] **BARC-03**: Barcodes not in the local database are looked up live in Open Food Facts and saved for next time
- [ ] **BARC-04**: When a barcode isn't found anywhere, user gets a pre-filled form to add the product
- [ ] **BARC-05**: Food data sources are attributed in the app (Open Food Facts / USDA)

### Workouts

- [ ] **WORK-01**: User can browse an exercise library filtered by muscle group and equipment (EN/RO names)
- [ ] **WORK-02**: User can create custom exercises
- [ ] **WORK-03**: User can log a workout session with exercises and sets (reps, weight)
- [ ] **WORK-04**: User can mark sets as warm-up or working sets
- [ ] **WORK-05**: User gets a rest timer between sets
- [ ] **WORK-06**: User sees their previous performance for an exercise while logging it
- [ ] **WORK-07**: An in-progress workout survives app restarts and poor connectivity
- [ ] **WORK-08**: User can view workout history
- [ ] **WORK-09**: User can see per-exercise progress (estimated 1RM, personal records, volume over time)
- [ ] **WORK-10**: User can start a new workout by repeating a previous one

### AI Coach

- [ ] **COACH-01**: User receives a daily insight card about the previous complete day, delivered in their local morning
- [ ] **COACH-02**: User receives a weekly review (consistency, macro balance, training volume, bodyweight trend, 2–3 suggestions)
- [ ] **COACH-03**: Every recommendation shows why it was made (the data and rule behind it)
- [ ] **COACH-04**: Recommendations are generated by deterministic, versioned rules based on the user's goal and logged data, and stored for auditability
- [ ] **COACH-05**: No advice is generated from incompletely logged days
- [ ] **COACH-06**: Sustained very low intake triggers a supportive safety message instead of deficit praise
- [ ] **COACH-07**: Coach text is in the user's language (EN/RO) and uses neutral, non-medical wording

### Admin

- [ ] **ADMN-01**: Admin can create, edit, and archive foods, including Romanian translations, via a web admin
- [ ] **ADMN-02**: Admin can create, edit, and archive exercises, including translations, via a web admin

### Platform

- [ ] **PLAT-01**: User can use the entire app in English or Romanian
- [ ] **PLAT-02**: Backend runs deployed in an EU cloud region and the mobile app runs on the author's phone
- [ ] **PLAT-03**: Database is backed up nightly off-server and restore has been tested

## v2 Requirements

Deferred to future release. Tracked but not in current roadmap.

### Account

- **ACCT-01**: User can delete their account and all data from inside the app — ⚠ **launch blocker**: required by Apple App Store and Google Play before any store release
- **ACCT-02**: User can export all their data (GDPR)

### Admin

- **ADMN-03**: Admin can list users, change roles, and disable accounts
- **ADMN-04**: All admin actions are recorded in an audit log
- **ADMN-05**: User-submitted foods go through an admin review queue

### Coach

- **COACH-08**: User can browse past insight cards and weekly reviews
- **COACH-09**: User can rate a card useful / not useful
- **COACH-10**: LLM-generated natural-language explanations (presentation only, never decisions)
- **COACH-11**: Target-adjustment proposals based on bodyweight trend

### Workouts & Nutrition

- **WORK-11**: User can save and reuse workout routines
- **NUTR-13**: User can save meals/recipes

### Engagement

- **NOTF-01**: Push notifications for insights and reminders
- **SOCL-01**: Social features (profiles, following, feed, likes, comments, check-ins)
- **GAME-01**: Gamification (points, streaks, badges)
- **TRNR-01**: Trainer Q&A (tickets)
- **WLLT-01**: Gym subscription wallet with renewal reminders
- **RWRD-01**: Rewards with partner gyms/brands

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| LLM-made health decisions | Safety — coach decisions are deterministic rules only |
| "Eat back" exercise calories | Breaks explainability and encourages over-eating estimates |
| Meal-photo AI recognition | Accuracy and complexity; not core |
| Automated meal plans | Non-goal until validated with safeguards |
| Wearable / biometric integration | Non-goal for initial phase |
| Micronutrient tracking | Data quality too poor in crowd-sourced sources; adds friction |
| Medical diagnosis or treatment | Non-goal; liability; keeps app outside medical device rules |
| Social login (Google/Apple) | Avoids App Store "Sign in with Apple" parity requirement in v1 |
| Python-native mobile UI | Research: weak barcode/store support — Python stays server-side |
| Storing raw payment card data | Never |
